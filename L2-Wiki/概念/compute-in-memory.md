# 存算一体/存内计算 · 打破冯·诺依曼瓶颈的架构革命

> **让计算在存储数据的地方就地完成，无需来回搬运数据——从架构层面消除"内存墙"，AI推理能效提升100倍+** | 技术 · 高级

---

## 一、生活化类比：厨房里直接炒菜——不需要从冰箱到灶台来回跑

想象你在做饭。传统厨房的布局是：冰箱在左边角落，灶台在右边靠墙，操作台在中间。做一道菜的过程是：从冰箱取食材→走到操作台切菜→拿到灶台下锅→炒好装盘→送回冰箱冷藏。每做一道菜，你就在冰箱和灶台之间来回跑十几趟。你真正花在"炒菜"上的时间只有20%，剩下80%的时间都在"搬运食材"。这不仅是浪费时间，还让你累得半死（功耗巨大）。

这就是冯·诺依曼架构下传统芯片的工作方式：CPU/GPU（灶台）和内存（冰箱）是物理分离的，数据必须在两者之间通过数据总线不断搬运。随着AI模型越来越大（菜谱越来越复杂），数据搬运的能耗和时间已经远远超过了实际计算的成本——这就是著名的"内存墙"（Memory Wall）瓶颈。

存算一体（Compute-in-Memory，CIM）的做法，就是在存储数据的存储器内部直接植入计算单元——就像在冰箱里装了一个迷你灶台。数据不需要搬出来，直接在存储位置完成计算（比如矩阵乘法）。只有最终结果需要传回CPU。搬运量降低了99%，功耗降低了90%以上。

存内计算的更极端版本：每个存储单元（就像冰箱里的每个食材盒）都自带计算能力——成千上万个迷你灶台同时开工，并行处理。这就是模拟存内计算的思路。

**对应关系：**

| 比喻中的元素 | 对应的技术/产业元素 |
|-------------|------------------|
| 冰箱（存放食材） | 存储器（DRAM/NAND/SRAM/新型NVM） |
| 灶台（烹饪） | CPU/GPU计算单元 |
| 从冰箱到灶台的来回跑动 | 冯·诺依曼架构下的数据搬移（占功耗90%+） |
| 冰箱里装迷你灶台 | 存算一体（Compute-in-Memory）：在存储器内嵌入计算单元 |
| 每个食材盒自带灶台 | 模拟存内计算（Analog CIM）：每个存储单元参与计算 |
| 跑动减少99% | 能效提升100倍+（数据移动量下降2-3个数量级） |

## 二、专业但通俗的定义

**全称**：Compute-in-Memory（CIM）/ Processing-in-Memory（PIM），存算一体/存内计算。核心思想是将计算单元（MAC/ALU）嵌入到存储器（DRAM/SRAM/NVM）内部或紧邻存储阵列，使数据在存储位置即可完成计算，消除传统冯·诺依曼架构中CPU和内存之间反复搬运数据的"内存墙"瓶颈。

**冯·诺依曼架构 vs 存算一体架构：**

| 对比维度 | 传统冯·诺依曼架构 | 存算一体架构 |
|---------|-----------------|------------|
| 存储与计算关系 | 物理分离，通过数据总线连接 | 深度融合，计算单元嵌入存储阵列内部 |
| 数据搬运 | 每条数据都要从内存搬到CPU/GPU再搬回（占能耗90%+） | 数据原位计算，仅搬移最终结果（搬运量降99%） |
| 能效比(TOPS/W) | GPU约1-5 TOPS/W | 模拟CIM可达500-1000+ TOPS/W（提升100-1000倍） |
| 适用计算类型 | 通用计算 | 以矩阵乘法/向量运算为主（与AI推理天然匹配） |
| 精度 | 32-bit FP/16-bit FP高精度 | 以8-bit INT以下为主，模拟CIM精度有限(需算法补偿) |
| 成熟度 | 数十年验证，高度成熟 | 早期商用阶段（三星HBM-PIM / Mythic / Untether AI） |
| 主要瓶颈 | 内存带宽不足（内存墙） | 模拟噪声/器件一致性/制造良率 |

**核心优势：**
1. **消除内存墙**：数据搬运减少99%+，从根本上解决冯·诺依曼瓶颈，AI推理延迟降低90%+
2. **能效提升100-1000倍**：模拟存内计算利用基尔霍夫电流定律直接在模拟域完成乘加运算，单次MAC操作能耗为数字计算的千分之一
3. **带宽不再是瓶颈**：计算发生在存储阵列内部，等效带宽等于整个存储阵列的并行读出能力（TB/s级别）
4. **天然适配AI矩阵运算**：AI推理的90%+计算量是矩阵乘法，而存算一体架构的物理本质就是大规模并行矩阵运算

## 六、投资关注点

1. **三星HBM-PIM的客户认证和大规模量产时间表**：这是存算一体当前最接近规模商用的产品形态，AMD MI300X的测试结果是重要信号
2. **SK海力士AiM的量产与客户验证**：基于GDDR6的方案更接近边缘推理场景，量产难度低于HBM-PIM，可能率先放量
3. **Mythic等模拟CIM企业的IPO与财务数据**：模拟存算一体的商业化进度是检验"能效100倍+"叙事真实性的关键
4. **HBM存储与PIM的结合趋势**：HBM4标准是否原生支持PIM功能，标准化的推进速度直接影响PIM生态的爆发节奏
5. **新型NVM器件(ReRAM/MRAM)的量产良率**：模拟CIM严重依赖新型NVM器件的一致性，器件良率决定芯片量产的可行性

## 七、风险提示

| 风险 | 如果发生，会怎样 |
|-----|----------------|
| 模拟CIM精度不足被拒 | AI推理对精度的要求不断上升(混合精度/FP8等)，模拟CIM的固有噪声和精度限制使其无法满足大模型需求→市场回到数字CIM路线，能效优势缩小 |
| 制造良率长期无法突破 | 模拟CIM对器件一致性要求极高(存储单元电阻偏差需<1%)→良率<50%→成本是传统方案3-5倍→经济性不成立 |
| GPU/NPU持续演进压制CIM | NVIDIA通过Blackwell/下一代架构的Transformer Engine等优化，将GPU能效每年提升30%+→存算一体的"100倍能效"优势被逐步追赶缩小 |
| 软件生态缺失 | 存算一体芯片需要全新的编译器和编程模型→开发者生态长期不成熟→只有少数客户愿意适配→无法形成规模效应 |
| 存储巨头"左右手互搏" | 三星/SK海力士的核心收入来自传统DRAM/HBM，PIM产品如果侵蚀传统业务毛利→内部资源投入摇摆→PIM研发被边缘化 |

## 八、如何判断是真逻辑还是炒概念

| 判断维度 | 应该看什么 | 小白容易误判的地方 |
|---------|-----------|------------------|
| 是否有真实流片和实测数据 | 是否有TSMC/Samsung代工的流片记录+第三方功耗/性能Benchmark | 把"论文发表了""拿了融资"当"芯片做出来了" |
| 客户认证是否在进行 | 是否进入AMD/Intel/云厂商的供应商测试流程 | 把"技术交流""战略合作"当"客户导入" |
| 收入/营收是否落地 | 存算一体芯片是否产生了规模收入(>1000万美元) | 把"政府补贴""研发拨款"当"产品收入" |
| 器件基础是否扎实 | 公司是否自研新型NVM器件/有自主存储工艺（还是依赖代工厂标准工艺） | 以为"在别人的存储上做计算"也算存算一体核心竞争力 |
| 与传统方案的对比是否有第三方验证 | 功耗/性能对比是否来自独立测试机构而非自测 | 把"理论上""模拟仿真"的数据当实测数据 |
