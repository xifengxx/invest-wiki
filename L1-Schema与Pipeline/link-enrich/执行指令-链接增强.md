# 链接增强执行指令

> **面向 LLM Agent 的执行提示。按步骤操作，不跳过。**

## 触发条件
用户说"增强链接""补充关联""enrich links"时，或新增赛道后。

## Step 1: 建立全局视图

1. Read `L2-Wiki/index.md` 获取所有赛道清单
2. 统计当前链接密度（总数、平均值、孤立赛道数）

## Step 2: 分批检查

每次处理 10 条赛道（避免上下文溢出），优先处理 backlinks 最少的：

1. Read 赛道的 YAML frontmatter，提取 `wikilinks`, `key_inputs`, `key_customers`
2. Read 赛道的 description 和 competition 正文
3. 列出该赛道所在的 layer，找到同层的其他赛道
4. 判断是否遗漏了以下类型的链接：
   - **上游**: key_inputs 中提到的赛道是否在 wikilinks 中
   - **下游**: key_customers 中提到的赛道是否在 wikilinks 中
   - **竞争**: competition 中提到的对手赛道
   - **同层**: 同 layer 的赛道，如果有技术关联
5. 对每个确认遗漏的链接，生成补全列表

## Step 3: 写入补全

对每条赛道，如果发现遗漏链接：

1. 更新 YAML frontmatter 中的 `wikilinks` 字段
2. 确保新增的链接名称精确匹配目标赛道的 `name` 字段
3. 对新增链接的目标赛道，检查是否需要反向链接（双向链接原则）

## Step 4: 验证

1. 重新编译 `L3-网页产物/build_wiki_data.py`
2. 检查孤立赛道数量是否下降
3. 检查 Graph 边数是否增加
4. 运行 Lint 确认无新增格式问题
5. 更新 `L2-Wiki/index.md` 统计

## 期望指标

| 指标 | 当前值 | 目标值 |
|------|:--:|:--:|
| 平均链接/赛道 | 2.1 | 5+ |
| Graph 边数 | 97 | 200+ |
| 孤立赛道 | 37 | <10 |
