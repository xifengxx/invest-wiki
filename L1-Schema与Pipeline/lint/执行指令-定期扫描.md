# 定期扫描执行指令

> **面向 LLM Agent 的执行提示。按步骤操作，不跳过。**

## 触发条件
用户说"检查知识库""lint""扫描""健康检查"时，或作为 cron 定时任务。

## Step 1: 遍历 Wiki

1. 列出 L2-Wiki/赛道/ 下所有 .md 文件
2. 对每个文件 Read，解析 YAML frontmatter
3. 同时检查 L2-Wiki/消化笔记/ 下的内容
4. 收集所有 wikilinks 形成关联图

## Step 2: 四维扫描

### 矛盾检测
- 提取所有实体的 name → 检查 wikilinks 指向的 name 是否存在于 L2-Wiki 中
- 对比消化笔记中的建议值与赛道当前值
- **发现矛盾后，写回到赛道 MD 文件的 YAML `contradictions` 字段**：
  ```yaml
  contradictions:
    - desc: "简短描述矛盾内容"
      source_a: "来源A路径或描述"
      source_b: "来源B路径或描述"
      status: "unresolved"
      found_date: "{当前日期}"
  ```
- 如果赛道已有 contradictions 字段，追加新条目（不覆盖已有条目）
- 如果 contradictions 中的某条已经解决（两个来源达成一致），更新 `status: "resolved"` 并填写 `resolved_date`

### 过期检测
- 检查 sources 字段中的年份（正则 `\d{4}`）
- 检查 key_trends 和 description 中的年份引用
- 检查消化笔记中判断句的时间窗口

### 孤立检测
- 统计每个赛道的 backlinks（被其他赛道 wikilinks 引用的次数）
- 检查公司是否出现在赛道的 companies 列表中
- 检查消化笔记是否被赛道引用

#### 新增赛道的接入检查（2026-09-13 新增）

**背景**：2026-08-18 新增的 7 个赛道（测试设备 / 封装设备 / 射频芯片 / MEMS 传感器 /
网络设备 / 企业级存储 / 大模型）因**只建了档、没接入图谱**，至今 backlink=0、
在可视化图谱中完全孤立。这类"建档即完成"的做法会持续累积孤岛。

**新建赛道时必须同时完成（缺一不可）**：
1. `wikilinks` 至少 3 条——与本产业链上下游赛道互链
2. `companies` 至少 3 个核心标的
3. `key_inputs` / `key_customers` 非空
4. **在被引用方的 `wikilinks` 中反向登记**——否则只是单向链接，对方仍是孤岛
5. 更新 `L2-Wiki/index.md` 对应产业分节（含分节计数）

**lint 检查项**：
- backlink = 0 且建档超过 30 天的赛道 → 🟡 警告
- `wikilinks` < 3 条 或 `companies` < 3 个 → 🟡 警告

### 重复建档检测（2026-09-13 新增）

**背景**：曾出现 **16 组赛道在「半导体」与「AI算力」各建一份**
（`半导体/semi-X.md` ↔ `AI算力/X.md`），自 init 起独立演进、内容分叉，
两份都进入编译产物——图谱上同一赛道显示两遍，且核心指标互相矛盾
（如 CPU 的 CAGR 10% vs 20%、成本占比 25 vs 10）。
事后清理需逐条合并 58 条趋势 / 34 条证据 / 61 个标的。拦截成本远低于清理。

**① 同名检查（按 name 精确匹配，跨目录）**：

```bash
python3 - <<'PY'
import glob, yaml, os, collections
n = collections.Counter()
for p in glob.glob('L2-Wiki/赛道/**/*.md', recursive=True):
    if 'index' in os.path.basename(p): continue
    d = yaml.safe_load(open(p, encoding='utf-8').read().split('---')[1]) or {}
    n[d.get('name')] += 1
dup = {k: v for k, v in n.items() if v > 1}
print(dup if dup else '无重名 ✅')
PY
```

> ⚠️ **`semi-` 前缀 ≠ 重复**。半导体目录中有大量**独立**赛道也带此前缀
> （光掩模版 / CMP 设备 / 测试设备 / 涂胶显影 / 离子注入…）。
> **禁止按前缀批量删除**，必须按 `name` 逐一比对。

**② `companies` 内部重复**（同一公司列两次，常表现为两种 ticker 写法，
如 `6488.TW` 与 `6488`、`3711` 与 `ASX`）：

```bash
python3 - <<'PY'
import glob, yaml, collections, os
for p in sorted(glob.glob('L2-Wiki/赛道/**/*.md', recursive=True)):
    d = yaml.safe_load(open(p, encoding='utf-8').read().split('---')[1]) or {}
    cs = [c.get('name') for c in (d.get('companies') or []) if isinstance(c, dict)]
    dup = {k: v for k, v in collections.Counter(cs).items() if v > 1}
    if dup: print(os.path.basename(p), dup)
PY
```

**③ 建档前查重**：新建赛道前，先按 name 与 slug 在全库搜索一遍
（`grep -rn "<赛道名>" L2-Wiki/赛道/`）。若同义赛道已存在于另一产业，
**优先决定归属哪个产业并复用**，而不是各建一份。

### 格式合规（基于 field-formats.md v2.0 结构化 YAML）

- **competition 类型检查**: 判断值是否为 dict（非 string），检查是否包含 `global`/`china`/`barriers`/`tech_gap` 子字段
- **competition 旧格式残留**: 如果是 string 且包含 `⚔️`/`||`/`🔒`/`📐` → 未迁移，🔴 严重
- **key_trends 类型检查**: 判断值是否为 list，元素是否为 `{title, detail}` 对象（非 string）
- **key_trends 旧格式残留**: 如果元素是 string 且包含 `——` 或 `|` 分隔符 → 旧格式
- **price_conduction 类型检查**: 判断值是否为 list of strings，单个 string → 旧格式
- **price_conduction 旧格式残留**: 如果是单一 string 且包含 `⇒` → 未迁移
- **sources 类型检查**: 判断值是否为 list，元素是否为 `{title, summary, url}` 对象（非 string）
- **sources 旧格式残留**: 如果元素是 string（`;` 分隔或 URL 在括号内）→ 旧格式
- **key_inputs/key_customers**: 判断值是否为 list，逗号分隔的单一 string → 旧格式
- **YAML 必要字段**: name, slug, type, industry, layer, tam, cagr, description 非空
- **⚠️ YAML 中禁止 Markdown 加粗（2026-09-13 新增）**: frontmatter 里若出现以 `**` 开头的裸值，
  YAML 解析器会把首个 `*` 当作 **alias（别名锚点）**，导致**整个 frontmatter 解析失败**、
  该实体在编译产物中退化为 `unknown`。
  - 典型触发：`key_trends` / `core_business` / `comparison` 等列表项写成 `- **xxx**`；
    以及 `revenue_model: **无独立收入**。...` 这类标量以 `**` 开头
  - 仅在 **frontmatter** 内受限；body 段内可正常使用 `**`
  - 同类需规避的开头字符：`*`、`&`、`!`、`%`、`@`、`` ` ``
  - **检测**：`python3 L3-网页产物/build_wiki_data.py` 输出中的 `unknown:` 必须为 **0**；
    非 0 即说明有 frontmatter 解析失败。全库逐文件校验：
    ```bash
    python3 - <<'PY'
    import glob, yaml
    bad = []
    for p in glob.glob('L2-Wiki/**/*.md', recursive=True):
        t = open(p, encoding='utf-8').read()
        if not t.startswith('---'): continue
        try: yaml.safe_load(t.split('---')[1])
        except Exception as e: bad.append((p, str(e)[:60]))
    print(bad if bad else '全部可解析 ✅')
    PY
    ```

## Step 3: 按严重度输出报告

使用 SKILL.md 中定义的四级输出格式：
- 🔴 严重：关联断裂、YAML 字段缺失
- 🟡 警告：过期、孤立、格式问题
- 🟢 提示：优化建议
- ✅ 统计数据

## Step 4: 生成修复建议

对每个 🔴 和 🟡 项，输出具体的修复操作：

```
修复建议:
1. GPU.wikilinks → "FPGA" → 确认路径: L2-Wiki/赛道/半导体/fpga.md (slug 正确但不在同一产业)
   → 建议: wikilinks 是跨产业有效的，无需修改。但需确认 FPGA 的 industry 字段。
2. MCU与嵌入式处理器: sources 过期 → 建议: 触发 collector 处理最新 MCU 行业数据
```

## Step 5: 等待用户确认修复

对于自动可修复的项（如格式合规），可以建议批量修复。
对于需要重新采集的项（如过期），建议触发 collector。

## Step 6: 更新索引

扫描完成后，更新 `L2-Wiki/index.md`：
1. 更新顶部的统计数字（赛道总数/链接数/质量版本/最后更新日期）
2. 如果发现新的孤立赛道或修复了断链，更新对应条目
3. 追加维护记录行
