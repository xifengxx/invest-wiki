# Invest Wiki 采集处理 Skill

## 一、核心定位

将原始研报/财报/新闻转化为 L2-Wiki 的结构化数据更新。遵循"先消化再更新"原则——所有新信息先写入消化笔记，评估影响后由用户确认执行更新。

## 二、五阶段流水线

```
┌─────────────────────────────────────────────────────────────┐
│  Stage 0: 完整读取与QA自检（Full Read & QA）                  │
│  ├── 完整读取原始资料全部页面/章节                             │
│  ├── 逐项完成7项QA自检清单（页数/章节/图表/数字/实体/判断句）   │
│  └── QA通过后方可进入Stage 1                                  │
├─────────────────────────────────────────────────────────────┤
│  Stage 1: 接收与归档（Receive & Archive）                    │
│  ├── 识别来源类型（研报/财报/新闻/行业数据/用户输入）          │
│  ├── 生成标准文件名 + 写入 YAML 头                            │
│  ├── 填写 Schema-Mapping 表（原文原句 → L2 赛道/公司/概念/论点）│
│  └── 保存到 L0-原始资料池/{类型}/                             │
├─────────────────────────────────────────────────────────────┤
│  Stage 2: 实体提取（Entity Extraction）                     │
│  ├── 从 Schema-Mapping 表提取赛道名/公司名/概念名              │
│  ├── 与 L2-Wiki 已有实体匹配（精确 > 模糊 > 新建候选）       │
│  └── 提取关键数据点（TAM 变化、份额变化、新趋势、风险点）      │
├─────────────────────────────────────────────────────────────┤
│  Stage 3: 消化笔记（Digest Note）                           │
│  ├── 保存到 L2-Wiki/消化笔记/{date}-{主题}.md              │
│  ├── 结构化提取 + 对已有赛道的影响评估 + 建议字段更新         │
│  └── 标记置信度（高/中/低）                                 │
├─────────────────────────────────────────────────────────────┤
│  Stage 4: 更新触发（Update Trigger）                        │
│  ├── 列出受影响赛道及其建议更新字段                          │
│  ├── 等待用户确认                                          │
│  └── 执行更新，回写 L0 文件 status                          │
└─────────────────────────────────────────────────────────────┘
```

## 三、分阶段执行

### Stage 0: 完整读取与QA自检（v1.1 新增）

**绝对禁止只读部分内容。** 必须覆盖原始资料的每一页/每一个章节。

读取完成后执行 **7项 QA 自检**：
1. 总页数/总字数确认
2. 全页面覆盖确认
3. 目录/章节核对
4. 图表/表格提取检查
5. 关键数字清单（所有带单位数字无遗漏）
6. 实体清单（所有公司/赛道/概念/产品名无遗漏）
7. 判断句清单（所有预测/结论/判断无遗漏）

**QA 未通过 → 禁止进入 Stage 1，必须补充读取。**

详细执行格式见 `执行指令-采集处理.md` Step 0。

### Stage 1: 接收与归档（含 Schema-Mapping，v1.1 增强）

**内容类型识别规则**（按优先级降序）：

| 触发特征 | 识别为 | 目录 |
|---------|-------|------|
| 包含"研报""研究报告""深度报告""首次覆盖""维持评级""目标价" | 研报 | `L0-原始资料池/01-研报/` |
| 包含"季报""年报""Earnings""10-K""10-Q""净利润""营收""毛利率" | 财报 | `L0-原始资料池/02-财报/` |
| 包含"新闻""快讯""报道""宣布""发布""上线" | 新闻 | `L0-原始资料池/03-新闻/` |
| 包含"TrendForce""IDC""Gartner""IC Insights""出货量""市场份额" | 行业数据 | `L0-原始资料池/04-行业数据/` |
| 用户直接发送的消息/文件/链接 | 用户输入 | `L0-原始资料池/05-用户输入/` |

**文件名格式**：
- 研报：`YYYY-MM-DD-标题-机构.md`
- 财报：`YYYY-MM-DD-股票代码-类型.md`
- 新闻：`YYYY-MM-DD-摘要.md`
- 行业数据：`YYYY-来源-主题.md`
- 用户输入：`YYYY-MM-DD-描述.md`

**Schema-Mapping 表（v1.1 新增，必填）**：

L0 归档文件必须包含结构化映射表，将原文内容**逐字段**映射到 L2 schema：

| 映射层级 | 映射内容 |
|---------|---------|
| 赛道层 | 原文原句 → 具体赛道 → 具体字段（tam/cagr/competition/key_trends等）→ 冲突标记 |
| 公司层 | 原文内容 → 具体公司 → 具体字段（one_liner/chain_role/suppliers等）→ 冲突标记 |
| 概念层 | 原文提及的概念 → 是否已有卡片 → 建议操作 |
| 论点层 | 原文判断/预测 → 支撑/挑战已有论点 → 建议操作 |
| 无匹配内容 | 无法映射但有潜在价值的内容 → 原因 → 价值评级 |

**关键规则**：每条映射的第一列必须是**原文原句或精确数据**，不能是 AI 自己的概括。这确保 Lint 追踪和后续验证有据可查。
- 用户输入：`YYYY-MM-DD-描述.md`

### Stage 2: 实体提取

**提取实体类型**：

| 实体类型 | 提取方法 | 匹配目标 |
|---------|---------|---------|
| 赛道 | 匹配 L2-Wiki/赛道/ 目录下的赛道名称 | 精确匹配 > 关键词匹配 > 新建候选 |
| 公司 | 匹配 L2-Wiki/公司/ 目录下的公司名称 | 精确匹配 > 股票代码匹配 > 新建候选 |
| 数据点 | 提取"数字+单位+指标"组合 | 匹配 segment-schema 的对应字段 |

**匹配策略**：
- 精确匹配（名称完全相同）→ 直接关联，置信度高
- 关键词匹配（名称部分匹配）→ 列出候选，置信度中
- 无匹配 → 标记"待确认"，可能为新实体

### Stage 3: 消化笔记

**必含内容**：
1. 关键提取（3-5 个要点）
2. 对已有赛道的影响评估（逐字段）
3. 新增实体清单
4. 风险标记
5. 判断句（供 Lint 追踪）

**影响评估格式**：
```markdown
### {{赛道名}}
- **tam**: {{当前值}} → {{建议值}}? ({{来源}}，{{置信度}}置信度)
- **competition**: {{变化说明}}
- **key_trends**: 建议新增 "{{趋势标题}}"
```

**置信度标记**：
- 高：来源明确、数字精确、报告权威
- 中：来源可靠但数字为估算
- 低：单一来源、推测性质

### Stage 4: 更新触发

**输出格式**：
```
📥 已归档: L0-原始资料池/{类型}/{文件名}

🏷️ 识别实体
- 赛道: GPU, AI服务器, HBM高带宽内存
- 公司: NVIDIA, AMD, TSMC

📝 消化笔记: L2-Wiki/消化笔记/{文件名}

🔄 建议更新（等待确认）
| 赛道 | 字段 | 当前值 | 建议值 | 置信度 |
|------|------|--------|--------|--------|
| GPU | tam | 130B | 140B | 高 |
```

**用户确认后**：
1. 更新赛道 MD 文件的对应 YAML 字段
2. 在 MD 正文追加 `## 动态更新记录` 小节
3. 回写 L0 文件：`status: 已处理` + `processed_date`
4. 回写消化笔记：`status: 已应用`

## 四、边界与异常

| 场景 | 处理方式 |
|-----|---------|
| 内容无法分类 | 标记"待分类"，保存到 L0 根目录，提示用户 |
| 实体匹配模糊 | 列出候选，标记"待确认"，不自动关联 |
| 新旧数据冲突 | 不覆盖，追加消化笔记，标记"待用户裁决" |
| 来源为重复内容 | 基于标题+URL 去重，标记"重复输入" |
| 无赛道受影响 | 仅归档，生成摘要消化笔记 |
| 用户拒绝更新 | 在消化笔记中追加"用户决定不更新"标记 |

## 五、与其他 Skill 的协同

| 协同 Skill | 关系 | 调用时机 |
|-----------|------|---------|
| `lint` (定期扫描) | 互补 | 采集的判断句自动进入 Lint 追踪池 |
| `schemas/` | 前置依赖 | 修改字段前必读对应 Schema |
